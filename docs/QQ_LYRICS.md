# QQ 优先中文译词

## 行为与兼容性

歌曲原词仍由 Spotify 优先、LRCLIB 补全；QQ 只提供对齐后的中文译词。
原词、时间轴、逐字信息与播放器布局不变，不使用机器翻译。

- 保留已有完整的官方或内嵌译词。需要外部中文译词时按 QQ → 网易云 → LRCLIB 查询，最后一路仍受「补全歌词」开关控制。
- 部分译词不会阻止继续补查；只有覆盖更多正文行且不丢失任何已译位置的整份结果才能替换。不同来源不逐行混合，底部标注实际采用的来源。
- 「社区歌词翻译」控制预加载，也供任务栏歌词使用；关闭预加载不禁用手动翻译与自动翻译。三种入口共用来源顺序与覆盖率规则，手动 / 自动翻译的简繁体仍跟随界面。
- 完整的内嵌译词不被预加载替换；非中文的部分内嵌译词也保留，用户可另行请求目标语言译词。
- 中文原词跳过中文译词预加载，不会因回退链新增 LRCLIB 等待；明确请求其他目标语言的行为不变。
- `LyricsResolver.qqTranslation` 为可选项；原有 `translation` 参数保留，`NeteaseTranslationLookup` 保留兼容别名。不提供社区源时，不会新增预加载网络请求。

## 匹配、网络与缓存边界

QQ 搜索仅发送曲名与主唱到固定 HTTPS 域名 `c.y.qq.com`，详情和译词请求发往 `u.y.qq.com`。
不读取或发送 Spotify / QQ 的账户 Cookie、令牌或登录信息，也没有新增依赖或登录流程。
设置中的中、繁、英、日文说明同步披露查询来源。

- 每次请求超时 3 秒、响应最多 512 KiB，不跟随重定向；限流及服务拒绝触发冷却，不立即重试。
- 最多两次搜索，每次最多解析十个候选；匹配歌手后优先完整曲名版本，再校验详情的歌曲 ID、艺人、时长（已知时差不超过 5 秒）与歌词类型。
- 原文文本锚点覆盖率至少 40%，不能只靠相近时间戳匹配歌曲。沿用当前对齐器的重复副歌、重复时间戳与最多三句相邻合句拆分规则，不跨间奏拼接。
- 只缓存确定的结果，包括确定无译词；错误、超时、畸形响应不缓存为「没有译词」。QQ 的 `qqmusic|v2|...` 键与其他来源隔离，重新获取和清空歌词缓存同时使迟到的缓存写入失效。
- 补查失败仍保留可阅读的已有译词；没有任何译词且查询失败时显示可重试状态。取消翻译 / 换歌时继续使用现有 revision 防护，迟到的 QQ 结果不能恢复被取消的翻译。

## 验证

离线回归使用合成歌词与 HTTP 替身，覆盖：请求大小 / 超时 / 重定向 / 限流、匹配与缓存、合句拆分、QQ 优先、部分结果继续补齐、拒绝丢行候选、原文保留、取消和清缓存竞态、来源显示。

```sh
flutter test test/lyrics test/spotify_provider_test.dart test/ui/android_lyrics_test.dart
```

可选匿名在线冒烟测试只输出曲目标识、行数、阶段和耗时，不记录歌词正文或账户数据：

```sh
flutter test tool/lyrics/qq_music_probe.dart
```

QQ 接口为外部服务，连通性、限流与译词覆盖会变化。在线探针不是登录账号或手机实播验证；发布时应另记录当次测试结果和安装版本。
